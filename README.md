
# 🔗 LinkBeam

**Открытый, локальный, кроссплатформенный аналог AirDrop для Windows, macOS и Linux.**

LinkBeam находит другие ПК в твоей Wi-Fi/LAN-сети сам, без единого аккаунта,
облака или регистрации, и позволяет перекидывать файлы между ними в два клика
прямо из браузера. Все данные идут напрямую между устройствами по локальной
сети — ничего не покидает её пределы.

## Почему это круто

- **Без облака и аккаунтов.** Ни один байт вашего файла не уходит дальше
  локальной сети. Никаких логинов, API-ключей и трекеров.
- **Кроссплатформенно.** Один и тот же Python-код работает на Windows, macOS
  и Linux — то, чего не хватает штатному AirDrop (только Apple) и многим
  форкам.
- **Zero-config.** Устройства находят друг друга автоматически через
  mDNS/Zeroconf — тот же механизм, что использует Chromecast и сетевые
  принтеры. Ничего не нужно настраивать.
- **С подтверждением, как в AirDrop.** Входящий файл нельзя получить без
  явного нажатия «Принять» — на экране получателя всплывает карточка с именем
  отправителя, размером файла и проверочным кодом.
- **Резервный сценарий на случай блокировки mDNS.** Многие
  корпоративные/гостевые сети режут multicast-трафик — на этот случай есть
  ручное подключение по IP:порт.
- **Интерфейс — просто веб-страница.** Никаких Electron-гигабайтов: LinkBeam
  поднимает лёгкий локальный сервер и открывает обычную вкладку браузера.

## Как это работает (коротко)

1. Ты запускаешь `linkbeam` на двух (или больше) компьютерах в одной сети.
2. Каждый инстанс объявляет себя в сети через mDNS (`_linkbeam._tcp.local.`)
   и одновременно слушает, кто ещё объявился рядом.
3. В открывшейся веб-странице ты видишь остальные устройства на «радаре».
4. Кликаешь по устройству → перетаскиваешь файл → на другой стороне всплывает
   запрос на подтверждение → после принятия файл льётся напрямую по HTTP
   в локальной сети и сохраняется в папку `LinkBeam Received`.

## Установка

Нужен Python 3.9 или новее.

```bash
git clone https://github.com/kilka888/linkbeam.git   # Если не работает, то просто установите linkbeam с этой страницы
cd linkbeam   # Укажите путь до папки linkbeam
pip install -r requirements.txt
```

Либо через `pip install -e .`, если хочешь получить команду `linkbeam` в PATH:

```bash
pip install -e .
```

## Запуск

```bash
python -m linkbeam
```

или, если ставил через `pip install -e .`:

```bash
linkbeam
```

При запуске откроется браузер со страницей `http://127.0.0.1:47111`
(порт можно изменить), а в консоли появится баннер с именем и ID твоего
устройства:

```
device name : MacBook Pro
device id   : 8f2ac1e9b3aa
save folder : /Users/you/LinkBeam Received
local url   : http://127.0.0.1:47111
```

Повтори то же самое на других ПК в этой же сети — они появятся друг у друга
на «радаре» в течение пары секунд.

### Полезные флаги

| Флаг            | Что делает                                              |
|-----------------|----------------------------------------------------------|
| `--port 47500`  | Запустить на другом порту                                |
| `--name "Имя"`  | Задать отображаемое имя устройства                        |
| `--no-browser`  | Не открывать браузер автоматически                        |

## Как отправить файл

1. Открой LinkBeam в браузере на устройстве-отправителе.
2. Кликни по кружку нужного устройства на радаре слева — он подсветится.
3. Перетащи файл в зону справа (или кликни, чтобы выбрать через проводник).
4. На принимающей стороне появится карточка с именем файла и кодом
   подтверждения — нужно нажать **«Принять»**.
5. Прогресс передачи отображается в реальном времени на стороне отправителя,
   а готовый файл окажется в папке `LinkBeam Received` (или в той, что задана
   в настройках) у получателя.

### Устройство не появляется на радаре?

Некоторые сети (корпоративные, гостевые Wi-Fi, часть VPN) блокируют
multicast-трафик, на котором работает автообнаружение. В таком случае:

1. Разверни блок **«Устройство не найдено? Подключиться по IP»** под радаром.
2. Узнай локальный IP-адрес и порт LinkBeam на другом устройстве (см. баннер
   в консоли или `/api/me`).
3. Введи их и нажми «Добавить» — устройство появится в списке как обычно.

## Автоприём

Тумблер **«Автоприём»** в шапке отключает запрос подтверждения — полезно,
если ты доверяешь всем устройствам в своей сети и хочешь пересылать файлы
без лишних кликов (например, между своими же ноутбуком и десктопом).

## Архитектура проекта

```
linkbeam/
├── linkbeam/
│   ├── __main__.py       # точка входа: конфиг, discovery, запуск сервера
│   ├── config.py         # идентичность устройства и настройки (~/.linkbeam)
│   ├── discovery.py      # объявление и поиск через mDNS/Zeroconf
│   ├── client.py         # логика отправки: запрос → ожидание → стриминг файла
│   ├── server.py         # Flask: веб-UI + приём/раздача, история передач
│   ├── storage.py        # журнал переданных файлов (~/.linkbeam/history.json)
│   └── web/
│       ├── templates/index.html
│       └── static/{style.css, app.js}
├── tests/                # smoke-тесты (не требуют реальной сети)
├── requirements.txt
└── pyproject.toml
```

Протокол передачи — обычный HTTP по трём шагам:

```
sender                              receiver
  │  POST /api/receive/request        │
  │  {sender_name, filename, size} ──▶│  создаёт заявку, ждёт решения юзера
  │                                    │
  │  GET /api/receive/status/<id>  ──▶│  опрос, пока status == pending
  │◀────────────────────── accepted ──│  юзер нажал «Принять»
  │                                    │
  │  POST /api/receive/upload/<id> ──▶│  файл льётся чанками, пишется на диск
```

## Дорожная карта / куда развивать

- [ ] Шифрование транспортного соединения (сейчас это открытый HTTP —
      безопасно только в пределах доверенной локальной сети)
- [ ] Полностью потоковая передача без временного файла на диске отправителя
      (сейчас файл от браузера сначала пишется во временный файл, затем
      стримится дальше — надёжно, но с двойной записью для очень больших
      файлов)
- [ ] Пакетная отправка нескольких файлов и целых папок (zip на лету)
- [ ] Иконка в трее вместо консольного окна
- [ ] Уведомления ОС о завершении передачи

PR'ы приветствуются — это открытый проект, задумывался как основа, а не как
готовый продукт «раз и навсегда».
